# 数独实验报告

## 这个实验想说明什么

数独是最适合用来观察"模型做判断"的一个小游戏：每一步只需要回答一个简单问题
（这个空格填几），答案有对错（谜题只有一个解），而且填什么材料、怎么填，
完全由我们控制。

所以它能回答一个关键问题：**我们把事实准备得越清楚，模型是不是就能做得越好？**

## 具体测了三件事

1. 空格数量能不能当难度旋钮用——40 个空格简单、55 个难，中间拉开差距？
2. 一个会读约束条件来推理的裁判，是不是比一个"拿到同样材料但只是瞎蒙"的
   裁判强？
3. 什么时候约束推理不够用了？不够用的时候，是怎么失败的？

## 实验怎么做的

两个裁判都看不到答案（solution），只能看我们发布的东西：

- **约束推理裁判**：看每格剩下的可能数字，先找"只有一个可能"的，再找
  "某个数字在本行/本列/本宫里只能放这里"的，都没有就猜最小的；
- **随机裁判**：拿同一份可能数字，随机挑一个（种子固定，结果可复现）。

四种难度（40/45/50/55 个空格）× 每个难度 10 局。填错算一次失误，3 次失误
本局结束。

跑法：

```bash
python3 experiment.py
```

输出如下：

```
空格数 裁判                  胜   平均填对   平均失误
   40 约束推理              10/10      40.0          0.00
   40 随机                   10/10      40.0          0.00
   45 约束推理               8/10      37.8          0.60
   45 随机                  10/10      45.0          0.30
   50 约束推理               3/10      22.9          2.10
   50 随机                   5/10      30.5          1.80
   55 约束推理               0/10       8.1          3.00
   55 随机                   3/10      22.6          2.70
```

## 结果说明

### 难度旋钮是有效的

40 个空格两边都全胜；55 个空格两边都很难赢。45–55 这个区间用来区分强弱刚好。
原因：空格少的时候，系统选出来的下一格通常只剩一种可能，闭着眼都不会错；
空格多了，就要靠真正的搜索推理，错三次机会就没了。

### 一个没想到的结果：随机裁判赢了推理裁判

45 个空格时随机 10 胜、推理只有 8 胜；55 个空格时随机还能赢 3 局，
推理一局没赢。

原因不在推理本身，而在规则的一个小坑：

- "某个数字只能放这里"这种推理是不会出错的；
- 但当推理用不上时，约束裁判的兜底办法是**每次都猜最小的数字**。猜错了
  以后这个格子不会落盘，下一轮系统还是挑同一个格子，它还是猜同一个错答案——
  3 次机会全浪费在同一格上；
- 随机裁判会换着数字试，3 次机会里撞对的概率自然高得多。

也就是说：**问题出在"错了以后不会换个答案"，不是出在约束推理不行。**
这本身是个有价值的发现——它告诉我们，以后接真模型时，要把"已经猜错过哪几个
数字"也告诉裁判，胜率应该能明显回来。

### 对真 Jev 的预期

真 Jev 拿到的材料和本地裁判一样（包括每个数字"不可能"的原因），但它不会像
`cands[0]` 那样死脑筋。想试的话直接 `python3 jev_sudoku.py --judge jev`，
代码不用改。推荐从 45–55 个空格开始测。

## 结论

1. 空格数量是个好用的难度旋钮，推荐 45–55 区间；
2. 约束材料有用，但"猜错之后怎么办"和"怎么猜"同样重要——修法很明确：
   把本格已经错过的数字排除掉再猜；
3. 再往下（X-wing、链式推理这些高级技巧）是给真模型准备的台阶，
   正好用来看它的推理到底有多深。

完整数据在 `artifacts/experiment_difficulty.json`。

## 附：这个实验里 Jev 的请求与回复结构

### Jev 的角色

每一步只回答一个问题：**这个格子填 1-9 哪个数字**。选格子（挑约束最多的）、
整理棋盘和排除理由都是 harness 干的活。另配 9 个判断题（每个数字一个：
「填这里是否与唯一解一致」）用于生成 gold 和做偏离对照，真跑时这些判断题
可以和 choice 放在同一个请求里，一次往返全拿回。

### 请求长什么样（真实采样，seed=7）

```json
{
  "state": "Sudoku 9x9, zero-based (row,column). Dots are empty cells.\n3 5 1 2 7 6 . . 8   <- next cell (row 0, column 7)\n. . . 8 . . 3 5 .\n…",
  "model": "jev-latest",
  "questions": {
    "digit": {
      "type": "choice",
      "instructions": "Write exactly one digit into the named cell. Use the published row/column/box exclusions first …",
      "criteria": {
        "1": "Write 1 at (row 0, column 7). IMPOSSIBLE: it already appears in row 0.",
        "2": "Write 2 at (row 0, column 7). IMPOSSIBLE: it already appears in row 0.",
        "4": "Write 4 at (row 0, column 7). survives all three row/column/box checks.",
        "…": "共 9 个候选数字，每个带本格的排除理由"
      }
    },
    "fits_4": {
      "type": "boolean",
      "instructions": "If the cell (row 0, column 7) is filled with 4, is that the digit the puzzle's unique solution places there?"
    }
  }
}
```

设计要点：**排除理由写进 criterion**（「IMPOSSIBLE: it already appears in row 0」），
模型不用自己扫行列宫；禁填的数字也作为选项保留并标明不可能——分布里能看到
它对错误选项给了多少概率，这本身就是信息。

### 回复结构（choice）

```json
{
  "answers": {
    "digit": { "type": "choice", "choice": "4", "confidence": 0.9,
               "probabilities": { "1": 0.02, "4": 0.9, "…": 0.08 } },
    "fits_4": { "type": "noul", "noul": 0.97 }
  }
}
```

`choice` 字段直接是答案；`probabilities` 画成概率条；9 个 `fits_N` 的 noul 值与
gold（唯一解）逐位对照，就是偏离度量。

### 一次推理的运行路径

```
① MRV 从当前棋盘挑出约束最多的空格
② 算该格的行/列/宫已用数字，生成候选
③ render_request 组装棋盘文本 + 10 个问题（1 choice + 9 boolean）
④ SDK 序列化 → POST /v1/systemone
⑤ 回复校验 → 取 answers['digit'].choice
⑥ step()：对则填盘并 score+1，错则 mistakes+1（错误不入盘）
⑦ 棋盘全满 → win；mistakes 到 3 → three_mistakes
```

代码位置：`sudoku_game.py` 的 `render_request` / `make_record` / `step`。

## 附：Jev 扮演什么角色、花多少钱、要等多久

### Jev 在这个实验里干什么

每一步只回答一个问题：这个格子填 1-9 哪个数字。我们负责选格子（挑约束最多的）、把棋盘和每个数字「可不可能」的理由整理好，它只做「从剩下可能里挑一个」这个判断。填错会记失误，但**错误不入盘**——棋盘永远是真的，错的只是它的选择。

### 每次推理的请求规模与费用（实测）

- 请求体积：**4774 字节**（紧凑 JSON，含 棋盘文本 + 10 个问题（1 个选择 + 9 个该数字是否与解一致））
- 折合输入 token：约 **1,193**（按 4 字符约等于 1 token 估算，实际以 API 返回的
  `usage.input_tokens` 为准）
- 输出：只是一个选择加概率分布，约 20-60 token，**官方对输出免费**
- 定价（官方文档 `models.md`，2026-09）：输入 **$0.042 / 100 万 token**，输出 $0
- **单次推理成本：约 $0.00005**

### 响应时间

- 本地替身实测：0.02ms（50 次采样中位数）
- 真 Jev 参考：JevHarness 公开数据 median 259-269ms（Vercel 网关）
- 下面按 **260ms/次** 估算

### 玩一盘的耗时与总成本
