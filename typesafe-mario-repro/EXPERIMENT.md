# 马里奥复现实验报告

> 详细版（方法、逐帧取证、全部错误更正记录）见 [REPORT.md](REPORT.md)。
> 本报告按统一结构浓缩四个子实验的"意义—问题—过程—结果"。

## 1. 实验意义

[typesafe-mario](https://github.com/fhshaik/typesafe-mario) 是上游作者给出的一个完整
示范：让 Jev 直接选择《超级马力欧兄弟》的手柄输入，模型不看画面，只读由 NES 内存
解析出的结构化事实。复现它的意义在于验证一条完整的工程命题：**"harness 把可计算的
算术全部算好、把事实按语义分组发布，模糊判定模型就能直接驱动一个实时系统"**。
复现过程中暴露的每一个缺陷，都是这条命题在真实工程里的边界标注。

## 2. 说明的问题

| # | 子问题 | 判定 |
|---|---|---|
| A | 上游 harness 能否在本机真机（内置 ROM）上原样跑通？ | 引擎/ROM/RAM/解析器/策略/SDK 全链路 |
| B | 上游代码是否存在影响模型表现的缺陷？ | 两条显示路径的行为对比 |
| C | 模型的"眼睛"（local_grid 传感器）是否忠实？ | 网格 vs 相机基址真值的逐格对照 |
| D | 改进发布事实的质量（JevHarness 式 harness）能否提升表现？ | 受控 A/B |

## 3. 实验过程

### 实验 A：真机闭环 + 抬起沿缺陷

真环境（`gym-super-mario-bros` 自带 ROM）+ 真 2KB RAM + 上游原代码，仅模型 HTTP
一跳用本地替身。`ruff`/`pytest` 全过，真解析器读真 RAM 输出正确网格与地形事实。
发现 `--display none`（headless benchmark）路径缺少跳跃按键的抬起沿处理（dashboard
路径有，`runner.py:162`）：

```
真机 A/B（ab_real_env.py，同 ROM 同策略同种子）：
variant                   max_x  decisions_at_max_x  release_frames
baseline (as shipped)       594                 369               0
with release edge          1124                   1               5
```

### 实验 B：传感器盲区（分享展示中由用户观察触发）

用户发现"模型看到的碰撞网格里没有坑，却一直死在那里"。取证（x=1094，相机
971，⌊971/256⌋=3 为奇数）：上游解析器按关卡绝对坐标选 nametable 页，而真机的
页面缓冲跟随相机滚动——相机在奇数 256px 页时读错一页，**网格整片空白**（无坑、
无地面、无管道）。修复（`parser_fix.py`，上游零改动）：按 `camera = x −
((ram[0x86]−ram[0x071C]) % 256)` 推导基址重建网格。修复后 28 局死亡分布从
"全部堆在同一坑位"打散为 `[843×4, 1149, 1416]`，一局越过从未通过的 1104 大坑。

### 实验 C：决策粒度约束

World 1-1 第一座 4 格水管的起跳窗口实测仅 28.6px（跳跃弧峰值 68px@t25、滞空
47 帧、跨度 82px，全部真机实测）。上游默认 8 帧/决策，一拍横跨 21px——判定
经常整拍错过窗口。把 harness 声明参数 `--frames-per-decision` 降到 4：

```
同一策略：fpd=8 best_x=1124  →  fpd=4 best_x=3156   （×2.8）
```

### 实验 D：JevHarness 式 harness v1 vs v2

按 [JevHarness](https://github.com/TianyuCodings/JevHarness) 三模式重写 harness
（`mario_harness_v2.py`）：预计算起跳窗口判定、每动作带量化 criterion 的动态
问题、跨局死亡记忆蒸馏为教训。真机同种子 A/B：v2（900 / 1517）未胜过 v1
（1124 / 3156）。机制分析：规则替身不读文本，记忆注入后六局行为逐字节相同；
v1 的粗糙启发式在细粒度下近似"高频连跳"，恰好适合连续水管段。**负结果 +
机制归因**完整记录于 REPORT §10。

## 4. 实验结果说明

| 发现 | 证据强度 | 影响 |
|---|---|---|
| A. headless 缺抬起沿：同一策略 594 卡死（269 拍原地、269 次下令起跳未起跳）vs 加沿后 1124 | 真机 A/B，唯一变量 | 模型的指令未被输入层执行，且状态中无字段告知模型——"指令被忽略"对模型不可见 |
| B. 网格相机页错位：⌊camera/256⌋ 为奇数时模型主障碍传感器全盲（约占一半位置） | 真机逐格取证 + 用户观察吻合 | 解释全部"反复死在同一坑"记录；修复后死亡分布打散 |
| C. 决策粒度 8→4 帧使 best_x ×2.8 | 真机对照 | 对上游最有价值的单条优化建议 |
| D. 精细化事实发布未胜过粗糙启发式 | 真机 A/B 负结果 | 替身不读文本；"事实质量 → 模型表现"命题必须由真 Jev 验证，`TYPESAFE_API_KEY` 零改动接入 |

## 5. 结论与后续

四个实验合起来的叙事：**上游 harness 的想法是对的（事实分组 + 算术留给代码 +
判断交给模型），但两处实现缺陷（抬起沿、相机页）让模型在约一半的时间里处于
"指令无效 + 传感器失明"的状态**——任何模型侧优化都应在这两处修复之后才有意义。
后续工作按优先级：(1) 真实 Jev 接入跑通端到端；(2) 粒度默认值调整建议提交上游；
(3) 抬起沿与相机页两处修复提交上游 PR。
